# 书脉的评测、审查与优化记录

这份文档记录书脉发布之后怎样被反复检验和修改：每一轮怎么做，用了哪些评测，找到了什么，改了什么，以及最后一轮审查发现、还没有修的问题。评测用例在 `evals/`，单元测试在 `tests/`。

### TL;DR

- 七轮下来，三条主路径都用真实账号数据跑过并打分：首次整理、把剩下的书补进主题、分享前隐私检查。三条路径最近一次的得分分别是 12/12、10/10、6/6。

- 每一轮的独立审查都找到了上一轮修复带来的新问题，累计修了四十多处。最重要的一处是隐藏的书仍会出现在页面的主题卡片上，在真实数据上有 17 处泄漏，修复后为 0。

- 第七轮审查找到 9 个问题，其中两处与隐私有关，已在 `c3755f2` 修复；其余 7 个还没有修，列在第三节。

## 一、每一轮怎么做

一轮由五步组成，前一步的结果决定下一步查什么：

1. **定目标。** 先问 advisor 这一轮查什么。手里没有能复现的失败场景，就不开新的一轮。

2. **评测。** 起一个子 agent，按 SKILL.md 把一个真实请求从头跑到尾。没有真人回答，需要用户确认的地方写进 `outputs/ask-user.md`，然后按用户同意处理。每个用例在 `evals/<用例>/` 下：`prompt.md` 是用户的请求，`graders/` 里一个文件一条检查项。

3. **打分。** 另起一个打分 agent，只看产物、脚本日志和运行记录，逐条判断检查项，写出 `grading.json`。它还要单独列出检查项没有覆盖到的缺陷，这一栏常常比得分更有用。

4. **独立审查。** 再起一个审查 agent，只给它上一轮修复的 diff、SKILL.md 和 `references/`，不告诉它我们认为哪里有问题。它只报五类问题：

   - 错误的结果；

   - 误导人的提示；

   - 崩溃；

   - 丢失用户的改动或者页面上的隐私泄漏；

   - 文档和代码对不上。

   每一条都要给出触发条件和复现方式。审查只用 `tests/fixtures.py` 里的假客户端和临时库，不碰真实接口。

5. **修复。** 评测还在用 main 时，修复放在单独的 worktree 分支里做，避免评测中途换了代码。每个修复配一个单元测试，并且先确认这个测试在修复前的代码上会失败。然后用审查者自己的复现脚本再跑一遍，最后在真实库的副本上重跑脚本，核对打印出来的数字。全部通过后合并、推送。

几条实践中定下的规矩：

- 微信读书接口不支持并发。评测在拉数据时，别处一律不调接口，否则会触发 HTTP 499，把正在跑的评测拖垮。

- 评测工作区里是真实的笔记和想法，含有隐私内容，只留在本机，不进仓库。

- 停止条件：最新一次修复经过审查没有影响行为的问题，并且三条路径在当前代码上最近一次的评测都干净。只剩措辞问题时一次改完就停，不再为措辞开新的一轮。

## 三、第七轮审查的问题

以下是第七轮审查的结果，都已用复现脚本确认，按严重程度排列。前两条已经修复，其余尚未修复：

1. **已修复：书名带分隔点的隐藏书仍会泄漏。** `scripts/vault_read.py` 的 `parse_sources` 按分隔点切分观点来源时，会把 `[[查理·芒格的智慧]]` 这样的双链切成两半，`scripts/render.py` 因此认不出这是被隐藏的书，它的想法、划线和书名仍会出现在主题卡片上。`c3755f2` 改为先整体匹配双链和书名号，再按分隔点切分。

2. **已修复：主题时长仍计入隐藏的书。** 主题的时长取自卡片 frontmatter，页面没有按留下的书重算；书全部被隐藏的主题也还留在知识环上。`c3755f2` 改为按页面上留下的书重算时长和领域里的主题数，书全部被隐藏的主题不再上页面。

3. **主题文字检查漏报。** 第六轮为减少误报收窄了检查，结果漏掉了“28 岁的我才明白复利”“我妈确诊癌症后才读懂这本书”这类句子，“原本我”“来自我”也被当成概念词跳过。建议恢复宽口径的检查，同时让用户确认过的句子可以在配置里标记，以后不再重复出现。

4. **观点的 `text` 为 null 或数字时，校验能通过，正式运行写到一半崩溃。** 位置在 `scripts/topics.py` 的 `pick_for_topic`。

5. **同一条命令里同时用 `--exclude` 和 `--hide-books` 时，不是全有或全无。** 编号出错退出之前，`hideBooks` 已经保存，改正后重跑会多藏书。脚本自己的提示还建议分两次运行，和 SKILL.md 矛盾。

6. **主题的 `name` 或 `related` 里的 `topic` 不是字符串时，校验崩溃。**

7. **新加的识别词有误报。** gap 会匹配 Singapore，工时会匹配分工时代，几斤几两和被动收入也会被标出；主题文字里的我国、我军会被当成第一人称，30 个字的窗口还会跨过分号和冒号。

8. **`digest.py` 的帮助文字和现在的归类规则不一致。** 现在只有写进主题 `books` 或 `assign` 的书才算归类。

9. **`topics.json` 顶层不是对象时，`digest.py --new` 崩溃。**

## 四、怎么复现

- 单元测试：在仓库根目录运行 `python3 -m unittest discover -s tests -q`，Python 3.9 及以上都能跑。

- 评测：`evals/` 下每个用例目录有 `prompt.md`、`case.yaml` 和 `graders/`，这是 `claude plugin eval` 读取的格式，也可以按 skill-creator 的流程手动起 agent 跑。评测需要真实的 `WEREAD_API_KEY` 和一个空的 Obsidian 库。检查项里的数量是按作者账号写的，比如约 370 本书，换一个账号时按各自的数据判断。
