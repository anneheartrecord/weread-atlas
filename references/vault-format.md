# 库内文件格式

书脉的所有脚本都按这份约定读写文件。改格式就要同时改读写两边的脚本和测试。

## 目录

书脉只在 Obsidian 库里的一个根目录下工作，默认名字是 `微信读书`。下文的路径都相对于这个根目录。

```
微信读书/
  总览.md              领域、主题和阅读统计的入口页
  书/<书名>.md          每本有笔记的书一篇
  主题/<主题名>.md      每个主题一张卡片
  书房/index.html       渲染出来的书房页
  .atlas/              脚本的工作目录，Obsidian 默认不显示点开头的目录
    config.json        配置
    cache/             接口原始回包，按 bookId 一个文件；notebooks.json 是笔记本列表，readdata/ 存阅读统计的回包
    books.json         整理后的书目数据
    stats.json         阅读统计
    topics.json        agent 写的主题方案
    digest/            给 agent 读的书目摘要
```

## 生成区块标记

脚本写的内容放在下面这对标记之间：

```
<!-- weread-atlas:begin -->
……脚本生成的内容……
<!-- weread-atlas:end -->
```

重新运行时，脚本只替换标记之间的内容。标记之外用户写的任何东西都保持原样，位置也不动。文件里没有标记时，脚本把生成区块追加到 frontmatter 之后，原有正文挪到区块后面，并在区块和原正文之间空一行。

frontmatter 的规则相同：脚本只更新它管理的字段，用户自己加的字段保留，字段顺序保留。

## frontmatter 的写法

只用一个很小的 YAML 子集，保证不依赖第三方库也能解析：

- 每行一个 `键: 值`。
- 值是字符串、数字，或者行内列表 `[a, b]`。
- 字符串含有 `:`、`#`、`[`、`]`、`{`、`}`、`,` 或首尾空格时，用双引号包起来，内部的双引号写成 `\"`，反斜杠写成 `\\`。
- 字符串以 YAML 的特殊字符开头（`- ? : , [ ] { } # & * ! | > ' " % @` 和反引号），或者整串看起来像数字、`true`、`false`、`null`、`yes`、`no`、`~`，或者是空串时，也用双引号包起来。这样 `bookId` 读回来仍是字符串，Obsidian 的 YAML 解析器也不会出错。
- 列表里的元素规则相同，Obsidian 的双链写成 `"[[书名]]"`。
- 读取时也接受单引号字符串和 Obsidian 属性面板写出的多行列表（`键:` 下面每行 `  - 值`）。脚本没改动的字段，原来的写法原样保留。

## 书的笔记：`书/<书名>.md`

文件名是书名，去掉副标题和括号里的版本说明，再去掉文件名里不能用的字符：`\ / : * ? " < > |`、`#`、`^`、`[`、`]`。副标题按 `：`、`:`（两个数字之间的冒号除外）、`|`、`——` 切分。两本书清洗后同名时，后面那本加上作者名：`书名（作者）.md`；还重名就再加 bookId：`书名（作者，bookId）.md`。比较时不分大小写。

“后面那本”按第一次做笔记的先后排：`noteSort` 小的先占用书名。文件名一旦写进 `books.json` 就不再改变，以后新出现的同名书只会给自己加后缀，不会让已有笔记改名。

脚本管理的 frontmatter 字段：

| 字段 | 含义 |
|---|---|
| `书名` | 清洗前的完整书名 |
| `作者` | 作者 |
| `bookId` | 微信读书的 bookId，写成带引号的字符串 |
| `分类` | 微信读书的一级分类，例如 `经济理财` |
| `进度` | 阅读进度，0 到 100 的整数 |
| `读完` | 读完日期 `YYYY-MM-DD`，没读完时不写这个字段 |
| `最近阅读` | 最近阅读日期 `YYYY-MM-DD` |
| `时长` | 阅读小时数的下限，保留一位小数。来自每月读得最多的前 10 本，所以只能算下限 |
| `划线数` | 划线条数 |
| `想法数` | 想法条数 |
| `领域` | 列表。由主题步骤写入，没归类时不写 |
| `主题` | 列表，元素是 `"[[主题名]]"`。由主题步骤写入 |
| `封面` | 封面图片地址 |
| `链接` | 接口返回的 `readerLink`，没有时用 `deepLink`，都没有就不写 |

生成区块的正文：

```
<!-- weread-atlas:begin -->
> 主题：[[主题A]] · [[主题B]]

## 章节标题

- 划线原文
  - 💭 想法原文

## 另一个章节

- 划线原文

## 没有对应划线的想法

- 💭 想法原文
  > 想法对应的原文
<!-- weread-atlas:end -->
```

规则：

- 第一行的主题行只在书已归入主题后出现。
- 章节按原书顺序排列，章节内的划线按位置排序。
- 想法的 `abstract` 和某条划线的原文一致时（比较前去掉所有空白），想法挂在那条划线下面；原文对不上但章节和位置 `range` 一致时也算。同一条划线下有多条想法时，按时间顺序每条一行。对不上的想法，以及整本书的书评，放进最后一节，有对应原文时在下一行用 `  > ` 引出原文（微信读书允许不划线直接写想法，这类想法很多）；没有这种想法就不写最后一节。
- 划线所在章节不在接口返回的章节列表里时，归入最后的 `## 其他章节`，排在所有章节之后、`## 没有对应划线的想法` 之前。
- 划线和想法都逐字保留，不改写。原文里的换行替换成空格。

## 主题卡片：`主题/<主题名>.md`

frontmatter：

| 字段 | 含义 |
|---|---|
| `主题` | 主题名 |
| `领域` | 所属领域 |
| `书目` | 列表，元素是 `"[[书的文件名]]"`，按阅读时长从长到短 |
| `时长` | 书目里各书时长之和，保留一位小数 |

生成区块：

```
<!-- weread-atlas:begin -->
## 一句话结论

一句可以被反驳的判断。

## 核心观点

1. **观点**：一两句说明。 —— [[书A]] · [[书B]]
2. **观点**：一两句说明。 —— [[书C]]

## 我的想法

- 想法原文 —— [[书A]]
  > 当时划的那句

## 代表划线

- 划线原文 —— [[书B]]
<!-- weread-atlas:end -->
```

规则：

- 来源书之间用 ` · ` 分隔。来源不在书架上时，写成 `《书名》` 而不是双链。
- 我的想法最多 3 条，代表划线最多 10 条。两者都只从这个主题书目里的书中挑选，由脚本按与主题文字的相关度排序，同一本书的想法最多 1 条、划线最多 2 条。
- 页面渲染时按标题解析这四节。用户在区块里改的文字，在下次重新生成主题卡片之前都会显示在页面上。

## 总览：`总览.md`

整篇都在生成区块里：一段阅读统计摘要，然后每个领域一节，列出该领域的主题双链和书数。

## `.atlas/config.json`

```json
{
  "rootName": "微信读书",
  "title": "书房",
  "theme": "舆图",
  "topN": 50,
  "exclude": []
}
```

- `theme` 取 `舆图`、`羊皮纸`、`星空` 三者之一。
- `exclude` 是不想出现在书房页上的文字片段。任何想法或划线只要包含其中一段，渲染时就会被跳过。库里的笔记不受影响。

## `.atlas/books.json`

数组，每个元素是一本书：

```json
{
  "bookId": "3300064234",
  "title": "金钱心理学",
  "fileName": "金钱心理学",
  "author": "摩根·豪泽尔",
  "category": "经济理财",
  "cover": "https://…",
  "link": "https://…",
  "rating": 85.2,
  "progress": 100,
  "finished": "2023-06-24",
  "readAt": "2025-01-03",
  "hours": 2.5,
  "noteSort": 1730000000,
  "chapters": [{"title": "第一章", "highlights": [{"text": "…", "thought": "…或 null", "pos": 120}]}],
  "orphanThoughts": [{"text": "…", "quote": "…"}],
  "marks": 120,
  "thoughts": 12
}
```

`noteSort` 是 `/user/notebooks` 返回的 `sort`，也就是最近一次做笔记的时间，用来判断增量。

- 数组按 `noteSort` 从新到旧排列。只有书签、没有划线也没有想法的书不收录。
- `thought` 是挂在这条划线上的想法；有多条时按时间顺序用换行符 `\n` 连接，没有时为 `null`。
- `orphanThoughts[].quote` 是想法对应的原文，整本书的书评没有原文，为 `null`。
- `marks` 是划线条数，`thoughts` 是有文字的想法条数（含挂在划线上的和对不上的）。
- `rating` 是接口的百分制评分除以 10，没有评分时为 `null`；`finished`、`readAt`、`link` 没有时为 `null`。

## `.atlas/stats.json`

```json
{
  "generatedAt": "2026-11-06",
  "since": "2022-02-23",
  "totalHours": 510,
  "readDays": 748,
  "readBooks": 340,
  "finishedBooks": 120,
  "notes": 9000,
  "years": [{"year": 2025, "hours": 180.2, "days": 300, "finished": 40}],
  "months": [{"month": "2025-09", "hours": 36.4}],
  "hourly": [{"hour": 0, "hours": 10.1}],
  "categories": [{"name": "经济理财", "hours": 147, "count": 78}]
}
```

- `hourly` 共 24 项，按 0 点到 23 点排列。接口的 `preferTime` 从早上 6 点开始，需要转一下。
- `categories` 来自接口的 `preferCategory`，最多 8 项。
- 数字都换算成小时，时长保留一位小数，总时长取整。

## `.atlas/topics.json`

这一份由 agent 写，脚本负责校验：

```json
{
  "domains": ["投资与周期", "精力与习惯"],
  "topics": [
    {
      "name": "致富与守富的不对称",
      "domain": "投资与周期",
      "oneLiner": "致富靠冒险与乐观，守富只能靠节俭与谨慎",
      "books": ["金钱心理学", "富爸爸穷爸爸"],
      "viewpoints": [
        {"claim": "致富靠乐观，守富靠恐惧", "text": "……", "books": ["金钱心理学"]}
      ]
    }
  ],
  "assign": {"三体": "小说与闲书"}
}
```

- `books` 和 `viewpoints[].books` 里写书的文件名，写 `books.json` 里的完整书名也能认出来。主题的 `books` 和 `assign` 里的书必须在 `books.json` 里。`viewpoints[].books` 可以写不在书架上的来源，渲染成 `《书名》`，脚本会逐条提醒，但不算错误。
- `assign` 给没进任何主题的书指定领域，可选。没指定的书，领域留空，页面上归入未归类。
- 校验不通过时，脚本列出所有问题后退出，一个文件都不写。要检查的问题有：领域不在 `domains` 里、主题重名、主题的 `books` 或 `assign` 里的书名找不到、oneLiner 超过 40 个字、观点少于 2 条或多于 8 条、主题名含有文件名不能用的字符。
- 从 `topics.json` 删掉的主题，旧卡片不会被删除，脚本只列出来提醒。
